# Carbonline — Premium Carbon Fiber Steering Wheel E-Commerce Frontend

A production-structured Next.js 14 (App Router) + TypeScript + Tailwind storefront for a
carbon fiber steering wheel brand, built around Audi, BMW, Mercedes-Benz, and Porsche
performance platforms.

## Quick start

```bash
npm install
npm run dev
```

Then open `http://localhost:3000`.

## Stack

- **Next.js 14** (App Router, file-based routing, `generateStaticParams` for product/brand pages)
- **TypeScript** throughout
- **Tailwind CSS** with a custom design-token theme (`tailwind.config.ts`)
- **Framer Motion** for the hero parallax/scroll sequence and the cart drawer
- No external UI kit — every component is hand-built and lives in `/components`

## Icons

Navigation, brand cards, and feature icons use [`lucide-react`](https://lucide.dev). A few
inline SVGs remain for small one-off marks (FAQ +/–, mute/unmute) where a hand-drawn glyph
fits the spec-sheet aesthetic better than a stock icon.

## Design system

- **Colors:** Void Black `#0A0A0B`, Carbon Charcoal `#18181A`, Steel `#333335`,
  Off-White `#F2F1EE`, Signal Red `#C41E2E` — one accent color only, used deliberately.
- **Type:** `Big Shoulders Display` for headlines (condensed, industrial), `Inter` for body
  copy, `JetBrains Mono` for technical/spec data (prices, part refs, compatibility codes).
- **Signature motif:** the site is framed like an engineering spec sheet — thin corner
  brackets (`.spec-frame` in `globals.css`) and `REF.xx` part-number style labels appear
  throughout instead of generic decorative elements.

## Connecting a real backend

The frontend is intentionally decoupled from any specific backend:

1. **Products/brands/compatibility** — replace the arrays in `lib/data.ts` with calls to
   your CMS, Shopify Storefront API, or your own database. The types in `lib/types.ts`
   are the contract every component expects.
2. **Cart & checkout** — `lib/cart-context.tsx` holds cart state in memory. Swap `addItem`,
   `removeItem`, etc. for calls to your cart API. `/checkout` (`components/CheckoutForm.tsx`)
   has a clearly-marked panel where Stripe Elements (or another provider) should mount —
   nothing simulates a real charge.
3. **Contact form** — `components/ContactForm.tsx` currently just flips a `submitted` flag.
   Wire the `handleSubmit` function to your email/CRM endpoint (the optional photo upload
   input is already there for fitment requests). Instagram/WhatsApp links on `/contact` are
   placeholders — point them at your real accounts.
4. **360° viewer** — `components/ProductGallery.tsx` simulates rotation by cycling through
   the existing gallery images. Drop a real frame sequence into
   `/public/images/360/{slug}/frame-001.webp … frame-036.webp` and swap the `frames` array
   for that sequence; the drag/rotate interaction logic doesn't need to change.
5. **Video section** — `components/VideoSection.tsx` expects `/public/videos/carbonline-reel.mp4`.
   Drop in real footage at that path.
6. **Legal pages** — `/legal/privacy`, `/legal/terms`, `/legal/cookies` are clearly-labeled
   placeholders. Replace with real policies (ideally reviewed by a professional) before launch.

## Performance notes

- Images use `next/image` for automatic AVIF/WebP + responsive sizing.
- Hero and gallery images are the only ones marked `priority`; everything else lazy-loads.
- Framer Motion is scoped to the components that need it (hero, carbon showcase, cart) rather
  than wrapping the whole app.
- Run `npm run build` and check the Next.js output for route-level bundle sizes before deploying.

## SEO

- Per-page `generateMetadata` (product and brand pages) with Open Graph tags.
- JSON-LD `Product` structured data on product pages.
- Clean URLs: `/shop`, `/shop/audi`, `/product/audi-rs-carbon`, `/custom`, etc.

## Fonts

Fonts are **self-hosted** via `next/font/local` (`app/fonts/*.ttf`, wired up in `app/layout.tsx`)
rather than fetched from Google Fonts at build time via `next/font/google`. This is deliberate:
`next/font/google` makes a live network call to `fonts.googleapis.com` during `next build`, and if
that call stalls in a given build environment, the build can hang with no visible error. Self-hosting
removes that dependency entirely — the build never touches the network for fonts.

The three files are the official variable-font builds from Google's own `google/fonts` GitHub repo
(Big Shoulders Display, Inter, JetBrains Mono), all licensed under the SIL Open Font License 1.1 —
license texts are in `/THIRD_PARTY_LICENSES`. To swap in a different typeface, drop a `.ttf`/`.woff2`
into `app/fonts/` and update the `localFont()` calls in `app/layout.tsx`.

## Regenerating placeholder images

```bash
pip install Pillow
python3 scripts/gen_placeholders.py
```

This regenerates the branded placeholder set in `/public/images` — useful if you want to
restyle the placeholders before real photography is ready.
